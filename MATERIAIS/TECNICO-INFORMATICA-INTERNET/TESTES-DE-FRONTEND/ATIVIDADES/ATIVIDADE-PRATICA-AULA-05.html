CAPACIDADES

C5 — Desenvolver conjunto de testes automatizados

💡 SEU PAPEL EM TODAS AS QUESTÕES
Você, como aluno consultor, foi chamado para criar os testes de integração da tela de login e da vitrine de uma loja virtual, sem depender da API real, usando Vitest, Testing Library e MSW.
💡 COMO RESPONDER
Cada questão tem 3 tópicos, e cada tópico tem o seu campo. Responda somente o que o tópico pede: (1) o conceito ou o comando pedido; (2) o código pedido escrito por inteiro (handler do MSW, servidor.use, teste com findBy ou waitFor, expect com o matcher) ou os valores pedidos; (3) uma frase curta de justificativa quando o tópico pedir "explique" ou "justifique". Escreva o código como escreveria no VS Code. Respostas copiadas da internet ou de colegas recebem nota zero no tópico.
💡 COMO A CORREÇÃO FUNCIONA
cada tópico é comparado com o padrão de resposta do professor: conceito certo, código correto (rota e método do handler, status da resposta, espera assíncrona sem tempo fixo e matcher adequado) e justificativa com as palavras-chave do conteúdo. Nomes de testes e variáveis diferentes valem, desde que o código esteja correto; aspas simples ou duplas e ponto e vírgula opcional são aceitos. Erros de português não tiram nota se a ideia estiver clara.
💡 TELA DE LOGIN USADA EM VÁRIAS QUESTÕES (SRC/TELALOGIN.JS)
montarTelaLogin(container) monta um formulário com os campos de rótulo "E-mail" e "Senha", o botão "Entrar" e um parágrafo com role="status". Ao enviar, mostra "Carregando...", faz um POST em URL_API + "/login" (URL_API = http://localhost:3000/api) e, se a resposta for aceita, guarda o token no localStorage e mostra "Bem-vindo, " + nome; se não for, mostra a mensagem de erro que veio da API.
💡 SIMULAÇÃO PADRÃO (SRC/MOCKS/HANDLERS.JS)
o handler de POST /login responde 401 com { erro: "Credenciais inválidas" } quando o e-mail não é aluno@senai.br ou a senha não é 123456, e responde { nome: "Aluno", token: "mock-jwt-xyz" } quando as credenciais são válidas.
