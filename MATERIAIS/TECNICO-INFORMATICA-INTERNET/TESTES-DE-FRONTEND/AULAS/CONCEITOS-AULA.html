API, HTTP, JSON e DOM

01 // Conversa entre sistemas

Tudo começa com a ideia de um sistema oferecer serviços a outro.

Conceito

API

Application Programming Interface: um contrato que diz o que um sistema oferece e como pedir. Quem consome não precisa saber como funciona por dentro, só o que enviar e o que vai receber.

Analogia: o cardápio de um restaurante. Você pede pelo cardápio, a cozinha é invisível.

Liga com: API REST (um estilo de API), JSON (o formato da resposta) e métodos HTTP (os verbos do pedido).

Estilo de API

API REST

Uma API que usa o protocolo HTTP e trata tudo como recurso com um endereço (URL): alunos, aulas, pedidos.

  • Um recurso, uma URL: /alunos e /alunos/7.
  • O verbo HTTP diz a ação: ler, criar, trocar, apagar.
  • Sem estado: cada pedido leva tudo de que o servidor precisa.
  • Resposta quase sempre em JSON.

Liga com: métodos, códigos de retorno e parâmetros.

Ferramenta

Insomnia (ou outro)

Cliente de API: você monta o pedido (método, URL, cabeçalhos, corpo) e vê a resposta sem escrever uma tela. Serve para testar e explorar uma API.

Alternativas: Postman, Bruno, Thunder Client (VS Code) e o curl no terminal. 

curl -X GET https://api.exemplo.com/alunos/7

Liga com: todos os cards de HTTP: é onde você enxerga método, código e JSON de verdade.

02 // O pedido HTTP

Os verbos dizem a intenção. Em uma API REST, cada um tem seu papel.

Métodos

GET, POST, PUT, PATCH e DELETE

GET Ler. Busca dados, sem alterar nada. GET /alunos/7
POST Criar. Envia um novo recurso no corpo. POST /alunos
PUT Substituir. Troca o recurso inteiro. PUT /alunos/7
PATCH Alterar em parte. Só os campos enviados. PATCH /alunos/7
DELETE Apagar. Remove o recurso. DELETE /alunos/7

Liga com: o submit de um formulário costuma virar um POST (ou PUT/PATCH ao editar), e o que volta é avaliado pelos códigos de retorno.

Respostas

Códigos de retorno (status HTTP)

Todo retorno traz um número que resume o resultado. Os códigos HTTP padronizados vão de 100 a 599 (não existem códigos acima disso), em cinco famílias pelo primeiro dígito. No dia a dia, quase tudo cabe em 200, 201, 204, 400, 401, 403, 404, 422 e 500.

1xx Informativo. O pedido foi recebido, continue. Raro no dia a dia.
2xx Sucesso. 200 OK, 201 Created (criado), 204 No Content (deu certo, sem corpo).
3xx Redirecionamento. O recurso mudou de lugar: 301 (definitivo), 302 (temporário), 304 (use o cache).
4xx Erro de quem pediu. 400 pedido inválido, 401 sem login, 403 sem permissão, 404 não encontrado, 422 dados que não passaram na validação.
5xx Erro do servidor. 500 falha interna, 502/503 serviço fora do ar.

Liga com: a tela decide o que mostrar pelo código: 2xx mostra o resultado, 4xx mostra a mensagem de erro ao usuário, 5xx pede para tentar de novo.

03 // O que viaja no pedido

Os dados enviados e recebidos precisam de formato e de lugar certo.

Formato de dados

JSON

JavaScript Object Notation: texto leve em pares chave: valor, lido por praticamente toda linguagem. 

{
  "id": 7,
  "nome": "Ana",
  "ativo": true,
  "notas": [8.5, 9.0]
}
  • Tipos: texto, número, booleano, null, lista e objeto.
  • Chaves e textos sempre com aspas duplas.
  • JSON.parse() lê o texto; JSON.stringify() gera.

Liga com: é o corpo do POST e o corpo da resposta da API.

Entrada de dados

Parâmetros

O pedido pode levar informação em quatro lugares:

  • Caminho (path): identifica o recurso. /alunos/7
  • Consulta (query): filtros e paginação. /alunos?turma=3A&pagina=2
  • Cabeçalho (header): metadados, como Authorization e Content-Type.
  • Corpo (body): os dados em JSON de um POST/PUT/PATCH.

Liga com: no Insomnia, query, headers e body têm cada um sua aba, e o path vai na própria URL; no formulário, os campos viram o corpo ou a query.

04 // Do outro lado: a página

É na página que a resposta da API vira algo que o usuário vê e usa.

Estrutura

Elementos DOM

O navegador transforma o HTML em uma árvore de objetos, o Document Object Model. Cada tag é um nó que o JavaScript pode ler e mudar. 

const titulo = document.querySelector('#titulo');
titulo.textContent = 'Olá, Ana';

const lista = document.querySelector('ul');
const item = document.createElement('li');
item.textContent = 'Ana';
lista.append(item);
  • Buscar: querySelector, getElementById.
  • Criar e inserir: createElement, append.
  • Reagir: addEventListener('click', ...).

Liga com: o JSON da API é percorrido e vira elementos na tela.

Interação

Submit de formulários

Ao enviar um <form>, o navegador dispara o evento submit e, por padrão, recarrega a página. Em apps modernos você intercepta, valida e envia por fetch. 

form.addEventListener('submit', async (evento) => {
  evento.preventDefault();
  const dados = Object.fromEntries(new FormData(form));
  const resposta = await fetch('/alunos', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(dados)
  });
  if (!resposta.ok) return; // fetch só falha sozinho em erro de rede
  const criado = await resposta.json();
});

Liga com: usa o POST, manda JSON no corpo, lê o código de retorno e atualiza o DOM com o resultado.

Identificação e aparência

Atributos, ids, classes CSS e estilos

  • Atributos: informações na tag (type, name, value, required).
  • id: único na página; ótimo para achar um elemento.
  • class: pode repetir; agrupa elementos para estilizar e selecionar.
  • Estilos: regras CSS aplicadas por seletor (#id, .classe, tag). 
<input id="nome" name="nome" class="campo campo--erro" required>

/* style.css */
.campo { border: 1px solid #888; }
.campo--erro { border-color: crimson; }

Liga com: o name do campo vira a chave do JSON; a classe muda a aparência quando a API devolve um erro 4xx.

05 // Tudo junto

Fluxo completo

Do clique ao resultado na tela

Formulário>> submit>> POST + JSON>> API REST>> código 201>> JSON de volta>> DOM atualizado

O usuário preenche o formulário, o submit é interceptado, o JavaScript envia um POST com JSON para a API REST, a API responde com um código e um JSON, e a página usa essa resposta para criar ou alterar elementos do DOM, ajustando classes e estilos. No Insomnia você testa só o trecho do meio, sem a tela.
